# 02. Архитектура

## 1. Компоненты

```
 Браузер ───────────────────────────────────────────────────────────────────────────────
  Web-приложение (React)
   └─ Web Worker: парсер TG/TT → нормализованная модель (тексты только здесь)
        ├─ бесплатные метрики → экран сразу
        ├─ пакет агрегатов (без текстов) → gzip → API
        └─ тексты «моментов» по запросу отчёта (postMessage из iframe)
                                            │ HTTPS
 VPS в РФ (Docker Compose) ─────────────────▼────────────────────────────────────────────
  Caddy (TLS, статика) → api (FastAPI) → PostgreSQL
                          ├─ вход Google/Telegram, сессии, CSRF
                          ├─ разборы, журнал, промокоды, ЮKassa webhook
                          ├─ пакет → модель report.v1 → HTML-отчёт
                          └─ история TikTok (шифрование)
                         worker (arq + Redis): Google Sheets, снимок пользователей, очистка отчётов
                         bot (aiogram): привязка, гайды, напоминания, Stars
  ↘ бэкап БД → S3 в РФ;  ↘ события без ПД → Google Sheets;  ↙ словари ← Google Drive
```

## 2. Потоки данных

### 2.1 Сайт, бесплатная часть
Файл читается в воркере, парсится, бесплатные метрики считаются в TS. На сервер — только события `upload.parsed`, `analysis.free_computed` (корзины размеров, без содержимого).

### 2.2 Сайт, платный разбор
1. Галочки → `POST /runs` → сервер проверяет отпечаток (повтор ≤ 30 дней — бесплатно), админа или **атомарно резервирует** разбор; возвращает `run_id` и (для слов, мата, имён) словари.
2. Воркер собирает пакет `packet.v1` (docs/05), gzip, `POST /runs/{id}/packet`.
3. Сервер валидирует (pydantic), строит модель `report.v1` (`app/metrics/report_model.py`), рендерит HTML (`app/report/render.py`), сохраняет. При ошибке разбор возвращается.
4. Браузер опрашивает статус → открывает отчёт в iframe.

### 2.3 TikTok: история
С согласия пользователя браузер отправляет пары `(UTC-время, id видео)` каждой выгрузки (`POST /tiktok/history`), сервер склеивает с сохранённой историей (дедупликация по паре), хранит сжатой и зашифрованной (AES-GCM). Платные TikTok-сводки считаются по полной склеенной истории. Без согласия просмотры передаются в пакете разово.

### 2.4 Бот
v0.1: привязка, гайды, напоминания, баланс, промокод, покупка за звёзды. Фаза 9: приём файлов (локальный Bot API до 2 ГБ) → Python-парсер → тот же пакет и пайплайн; альбом TikTok-файлов → склейка.

### 2.5 Моменты (монологи и разговоры)
Модель отчёта хранит границы моментов (`i0`, `i1` — индексы сообщений в пакете). Кнопка «Текст» в отчёте отправляет `postMessage` родительскому окну; приложение берёт тексты из файла в воркере и показывает их. Сохранить: HTML-файл или «избранное» в браузере. На сервер тексты не уходят.

## 5. ADR — журнал решений

**ADR-001. Парсеры на TS и Python с паритетом по фикстурам.** Сайт считает в браузере (TS), бот — на сервере (Python, фаза 9). Общий контракт — packet.v1; паритет-тест на общих фикстурах. Pyodide отклонён (вес, скорость на 100+ МБ).

**ADR-002 (пересмотрен). Отчёт = модель report.v1 + встроенный JS-рендер.** Раньше: SVG на сервере. Теперь нужен выбор периода в любой сводке, поэтому сервер отдаёт факты с точностью до дня (ряды по дням, часы по дням, гистограммы скорости ответа, списки моментов), а маленький JS внутри HTML пересчитывает агрегаты за выбранный период. Плюсы: офлайн, один шаблон для HTML/PDF/PNG, мгновенное переключение периода. Цена: логика агрегации за период видна в отчёте — допустимо, отчёт получают только оплатившие; тяжёлые расчёты (сессии, моменты, ответы, словари) остаются на сервере.

**ADR-003. Словари выдаются браузеру только под оплаченный разбор.** Мат и имена нельзя считать по хэшам (нужны регулярки по корням), а тексты не уходят на сервер.

**ADR-004. ПД в РФ, Google — только обезличенное.** В таблицах `user_ref`, не email.

**ADR-005. Единый баланс сайта и бота.** Аккаунт — Google или Telegram; Telegram привязывается к Google-аккаунту.

**ADR-006. Один VPS в РФ вместо Vercel/Netlify.** См. docs/19.

**ADR-007. Время.** Храним настоящее UTC (`date_unixtime` в Telegram, `Date` в TikTok — UTC). Показываем в поясе города пользователя (`zoneinfo`/`Intl`). Пояс устройства экспорта Telegram (разница `date` и `date_unixtime`) — только подсказка в выборе города.

**ADR-008. Бот, воркер и API — один Python-пакет.** Общие модели БД и бизнес-логика; разные команды запуска в docker-compose.

**ADR-009. Метрики без pandas.** Чистый Python проще разворачивать, быстрее стартует, достаточно для 300 тыс. сообщений (~1–2 с).
