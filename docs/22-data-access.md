# 22. Где лежат данные и как их смотреть

## Что где хранится

| Что | Где | Сколько | Как смотреть |
|---|---|---|---|
| Пользователи, баланс, покупки, промокоды, разборы, события | PostgreSQL на VPS в РФ | всегда (события — 180 дней) | **Админка** `/admin`, **Google-таблица** `ops_log` (зеркало), при необходимости — прямой доступ к БД |
| Готовые отчёты (HTML) | диск VPS | 90 дней | у пользователя в «Мои отчёты», у вас — через админку |
| История TikTok (время + id видео, зашифровано) | PostgreSQL | пока пользователь не удалит | только в агрегатах (число просмотров, период) |
| Технические логи (JSON, без текстов и ПД) | Docker на VPS, ротация 10×50 МБ на сервис | ~1–4 недели | архив раз в сутки на **ваш Google Диск** в папку проекта (фаза 10) |
| Бизнес-события без ПД | таблица `events` + листы `events`/`errors` в Google-таблице | 180 дней в БД, в таблице — пока не очистите | админка → «Журнал», Google-таблица |
| Словари мата, имён | Google-таблица `dictionaries` на вашем Диске | — | редактируете прямо там |
| Тексты переписок | **нигде** (на сайте не покидают браузер; через бота — только в памяти на время подсчёта) | — | — |

## Три способа смотреть

### 1. Админка (основной)
`/admin` в приложении, вход — ваш Google-аккаунт (email в `ADMIN_EMAILS`).
- **Обзор:** новые и активные пользователи, загрузки, платные разборы, оплаты, выручка ₽ и ⭐, промокоды, ошибки; популярность сводок; период — сутки / 7 / 30 / 365 дней.
- **Пользователи:** поиск по email или `u_…`, карточка (баланс, история движений, платежи, разборы, события), начисление разборов с причиной.
- **Промокоды:** создание (на N разборов, скидка %, фиксированная цена; для одного или для всех; лимит; срок; свой код или автогенерация пачкой), включение/выключение, сколько раз применён.
- **Разборы:** статусы, ошибки, тайминги.
- **Журнал:** все события с фильтром по уровню и типу (`payment.*`, `run.*`…).

### 2. Google-таблица `ops_log` (зеркало, обновляется раз в минуту)
| Лист | Строка | Что видно |
|---|---|---|
| `users` | пользователь | `user_ref`, роль, создан, последний визит, привязан ли Telegram, **баланс разборов**, сколько куплено, **оплачено ₽ и ⭐**, сколько разборов сделано, последний разбор. Перезаписывается снимком раз в 10 мин |
| `orders` | покупка / промокод / начисление / возврат | время, `user_ref`, тип, способ (ЮKassa/звёзды/промокод/админ), продукт, разборов, сумма ₽, сумма ⭐, промокод (маска), статус |
| `runs` | разбор | время, `user_ref`, источник, тип чата, выбранные сводки, списание (платно / повтор / админ), статус, секунд, размер пакета |
| `events` | событие | время, уровень, тип, `user_ref`, разбор, данные (без ПД) |
| `errors` | ошибка | то же только для ошибок — удобно для фильтра |
| `daily` | день | формулы: пользователи, разборы, выручка, конверсия (настраиваете сами) |

Можно строить сводные таблицы и графики прямо в Google Sheets.

**Почему вместо email — `user_ref`.** Это не техническое ограничение (Google в России работает), а юридическое: по 152-ФЗ персональные данные россиян должны храниться в базе на территории РФ, а таблица Google — за рубежом. Псевдоним `u_…` не позволяет установить личность без доступа к нашей БД; по нему вы мгновенно находите человека в админке. Если решите всё-таки писать email в таблицу — это отдельное решение с юридическим риском (нужно уведомление о трансграничной передаче); технически это один флаг, но по умолчанию выключено.

**Можно ли сделать Google-таблицу основной базой?** Не рекомендую: у таблиц нет транзакций (два одновременных запроса могут дважды списать один разбор), жёсткие квоты API (~60 запросов в минуту), задержки в секунды и ограничение по объёму. Зеркало даёт ту же наглядность без этих рисков.

### 3. Прямой доступ к БД (на крайний случай)
Через SSH-туннель и программу DBeaver или веб-интерфейс Adminer. Настроит Claude по запросу; в обычной работе не нужен.
