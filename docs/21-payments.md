# 21. Оплата: ЮKassa и Робокасса

> Решение автора: **самозанятость (НПД)** и **ЮKassa в первой версии**. Робокасса — запасной вариант: код оплаты спрятан за интерфейсом провайдера, замена не трогает остальной сервис.
> Тарифы и условия у обоих сервисов меняются — цифры ниже ориентировочные, перед подключением сверить на сайтах (yookassa.ru, robokassa.com) и у бухгалтера.

## Сравнение

| | ЮKassa | Робокасса |
|---|---|---|
| Кто это | Платёжный сервис группы Сбера (бывшая Яндекс.Касса) | Независимый агрегатор, работает с 2003 г. |
| Самозанятым | Да, отдельное подключение по ИНН самозанятого. Чек в «Мой налог» может регистрироваться автоматически (проверить при подключении, что опция включена) | Да, отдельный тариф для самозанятых с автоматической передачей дохода в «Мой налог» |
| Комиссия для самозанятых | ориентир ~3–3,5% с платежа | ориентир ~3,5–4% и выше; зависит от способа оплаты |
| Способы оплаты | Карты (Мир, Visa/MC российских банков), SberPay, СБП, ЮMoney — набор для самозанятых может быть уже, чем для ИП | Карты, СБП, SberPay, Mir Pay, электронные кошельки |
| Интеграция | Современный REST API v3, JSON, официальный Python SDK, тестовый магазин с тестовыми картами, повторный запрос платежа по id | Перенаправление на форму с подписью MD5/SHA (`MerchantLogin`, `OutSum`, `InvId`, `SignatureValue`), уведомление на `ResultURL` с подписью; документация старее |
| Уведомления | HTTPS-webhook без подписи → проверяем перезапросом платежа по API и по IP-адресам (так и сделано) | Уведомление подписано паролем магазина — проверка подписи |
| Возвраты | Через API (`POST /refunds`), чек возврата автоматически | Через личный кабинет или API |
| Тестирование | Тестовый магазин, тестовые карты, полный цикл webhook | Тестовый режим `IsTest=1` |
| Модерация сайта | Нужны: оферта, контакты, описание услуги, цены, политика ПД, работающий сайт | Примерно те же требования |
| Выплаты | На карту/счёт самозанятого | На карту/счёт |

## Почему ЮKassa в v1
1. **Удобный API и тестовый магазин** — можно проверить весь цикл до запуска, автоматические тесты уже написаны (`apps/api/tests/test_api.py`).
2. **SberPay и СБП** — самые конверсионные способы для аудитории в РФ.
3. **Идемпотентность** (`Idempotence-Key`) и перезапрос платежа — надёжное «заплатил → получил».
4. **Возвраты через API** — кнопка в админке.

## Подводные камни
- **Модерация.** Подключение одобряют, когда сайт уже работает и на нём есть оферта, политика ПД, цены и контакты. Поэтому оплату подключаем в фазе 12, когда сайт доступен по домену.
- **Лимит НПД — 2,4 млн ₽ в год.** При превышении статус теряется → ЮKassa перестанет принимать платежи на самозанятого. Перед этим перейти на ИП (УСН 6%) и переподключиться.
- **Чеки.** Для НПД чек — из «Мой налог». Убедитесь, что автоматическая регистрация дохода в ЮKassa включена; иначе чеки придётся пробивать вручную (сервис этого не делает). В коде флаг `YOOKASSA_SEND_RECEIPT=false` — объект чека по 54-ФЗ не передаём.
- **Webhook без подписи.** Защита — перезапрос платежа по id + список IP ЮKassa (`app/billing/yookassa.py`). Список IP сверить с документацией перед запуском.
- **Блокировки.** Платёжные сервисы могут приостановить приём при всплесках возвратов или жалоб. Политика «отчёт не построился — разбор вернётся автоматически» снижает риск.
- **Telegram Stars и НПД.** Доход в звёздах выводится через Fragment в TON. Можно ли самозанятому учитывать такой доход и как — **вопрос к бухгалтеру** (см. OPEN-QUESTIONS). Технически оплата звёздами в боте уже реализована, её можно выключить флагом.

## Как устроено в коде
- `app/billing/yookassa.py` — клиент API (создание платежа, получение, возврат) и проверка IP.
- `app/billing/router.py` — `POST /payments/yookassa`, webhook, тестовая оплата для локальной разработки (`mock`).
- `mark_succeeded()` — единая идемпотентная точка начисления разборов (ЮKassa, Stars, тест).
- Замена на Робокассу: добавить `app/billing/robokassa.py` (формирование ссылки с подписью + проверка подписи `ResultURL`) и переключатель провайдера в конфиге.
