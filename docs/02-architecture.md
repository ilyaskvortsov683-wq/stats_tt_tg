## 2. Потоки данных

### 2.1 Сайт, бесплатная часть
1. Пользователь выбирает файл. Файл читается в Web Worker (`File.stream()` + потоковый JSON-парсер для файлов > 100 МБ).
2. Парсер строит нормализованную модель (`docs/03-data-formats.md`, раздел «Нормализованная модель»).
3. Бесплатные метрики считаются в TS и рисуются сразу. Сети нет.
4. На сервер уходит только событие `analysis.free_computed` (источник, тип чата, размер-корзина, длительность) — без содержимого.

### 2.2 Сайт, платный разбор
1. Пользователь ставит галочки → «Сделать разбор».
2. `POST /runs` — сервер проверяет баланс/отпечаток, **резервирует** разбор, возвращает `run_id`, `ticket` и словари, нужные для выбранных сводок (мат, имена, смех, стоп-слова).
3. Браузер собирает пакет агрегатов (`docs/05`) только для выбранных сводок, сжимает gzip, `POST /runs/{id}/packet`.
4. Сервер валидирует пакет (pydantic, версия схемы), кладёт задачу в очередь.
5. Worker считает платные метрики, рендерит HTML, сохраняет, **подтверждает списание**. При ошибке — снимает резерв.
6. Браузер опрашивает `GET /runs/{id}` (или SSE) → открывает отчёт, кнопки экспорта.

### 2.3 TikTok: история просмотров
- Браузер извлекает пары `(timestamp, video_id)` и отправляет их отдельно (`POST /tiktok/history`) — это не текст переписки, а личная история; хранится зашифрованно, по согласию (галочка «Сохранять историю для склейки», по умолчанию включена, с пояснением).
- Сервер склеивает с уже сохранённой, дедуплицирует по `(timestamp, video_id)`.
- Платные сводки просмотров считаются на сервере по полной склеенной истории.

### 2.4 Бот
- Файлы приходят на сервер (иначе нельзя). Обрабатываются **в памяти** Python-парсером → тот же пакет агрегатов → тот же пайплайн. Исходный файл удаляется сразу после разбора (и с диска локального bot-api сервера).
- Альбом из нескольких TikTok-файлов → склейка.
- Бот также открывает Mini App (тот же веб-интерфейс), где обработка идёт в браузере, — рекомендуемый путь для чатов.

## 3. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Web | React 18, Vite, TypeScript | зрелая экосистема, исполнителю проще всего |
| Стили | CSS Modules + CSS-переменные из `packages/design-tokens` | полный контроль над видом, темы через переменные, без «типового» UI-кита |
| Доступные примитивы | Radix Primitives (Dialog, Checkbox, Tabs, Tooltip) | доступность без навязанного стиля |
| Графики в приложении | собственные SVG-компоненты (React) по тем же спецификациям, что и в отчёте | единый вид в UI и в отчёте |
| Парсинг | Web Worker, `@streamparser/json` для больших файлов | UI не зависает |
| API | FastAPI, pydantic v2, SQLAlchemy 2 (async), Alembic | Python — язык автора; перенос из ноутбуков |
| БД | PostgreSQL 16 | транзакции для журнала разборов |
| Очередь | Redis + arq | простые async-задачи, cron-задачи |
| Метрики (сервер) | pandas / numpy | перенос из ноутбуков |
| Морфология имён | pymorphy3 | генерация падежных форм имён |
| Отчёт | Jinja2 + серверный SVG | работает офлайн, одинаково в HTML и PDF |
| PDF/PNG | Playwright (Chromium) | точная печать того же HTML |
| Бот | aiogram 3, webhook; `aiogram/telegram-bot-api` локально | файлы больше 20 МБ |
| Логи | structlog → stdout (JSON) + таблица `events` | см. docs/14 |
| Google | `google-api-python-client`, сервисный аккаунт | Sheets, Drive |
| Платежи | ЮKassa API v3 (сайт), Telegram Stars (бот) | см. docs/09 |
| Инфра | Docker Compose, Caddy, GitHub Actions | один VPS, автоматический TLS |

## 5. ADR — журнал архитектурных решений

### ADR-001. Парсеры на TS и на Python с паритетом по фикстурам
**Контекст:** сайт считает в браузере (TS), бот получает файлы на сервер (Python).
**Решение:** два парсера и два сборщика пакета. Общий контракт — `packages/schema`. Golden-тест: на каждой фикстуре TS и Python обязаны выдать байт-в-байт одинаковый (после канонизации) пакет.
**Альтернатива:** Pyodide в браузере (один код на Python) — отклонено: 10+ МБ загрузки, медленный разбор файлов 300 МБ.

### ADR-002. Отчёт рендерится на сервере, графики — SVG
Один шаблон даёт HTML, PDF и PNG; темы переключаются CSS-переменными внутри SVG; отчёт открывается офлайн.

### ADR-003. Словари матчинга выдаются браузеру только под оплаченный разбор
Мат/имена нельзя посчитать по хэшам (нужны регулярки по корням), а тексты не должны уходить на сервер. Поэтому браузер получает словари вместе с `ticket` разбора и отправляет только счётчики совпадений. Сами словари — не секрет, секрет — серверная логика отчёта; этого достаточно.

### ADR-004. Хранение ПД в РФ, Google — только обезличенное
См. docs/18. Google Sheets получает `user_ref` (HMAC от user_id), а не email.

### ADR-005. Единый баланс разборов для сайта и бота
Аккаунт = Google-пользователь; Telegram привязывается к нему. Покупка звёздами в боте пополняет тот же журнал.

См. docs/19.
