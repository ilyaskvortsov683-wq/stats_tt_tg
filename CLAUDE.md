# CLAUDE.md — правила для исполнителя

Этот файл читается Claude Code автоматически в каждой сессии. Следуй ему всегда.

## Об авторе и процессе

- Автор — программист (Python, статистика), но **не работает с командной строкой**. Все команды запускаешь ты; автор только подтверждает действия.
- Язык общения, документации, комментариев к коммитам и UI — **русский**. Идентификаторы в коде — английские.
- **Коммит — один на одно сообщение автора, в самом конце**, когда результат проверен (тесты/линтеры прошли). Затем пуш в рабочую ветку. Никаких промежуточных коммитов.
- Деплой на сервер — **только по явной команде автора**.
- Pull request не создавай, пока автор не попросит.
- Перед началом фазы прочитай: `docs/ROADMAP.md` (раздел фазы) и все документы, на которые фаза ссылается.
- Если что-то в документах противоречит запросу автора — запрос автора главнее, но обнови документ в том же коммите.
- Решение, которое меняет архитектуру, фиксируй в `docs/02-architecture.md` (раздел ADR).

## Скиллы

- Когда начинаешь пользоваться скиллом, **первой строкой ответа напиши**: `🔧 Скилл: <имя> — <зачем>`. Автор хочет видеть это сразу.
- Перед любым графиком, тепловой картой, KPI-плиткой — загрузи скилл `dataviz`.
- Перед любой работой над интерфейсом или шаблоном отчёта — загрузи проектный скилл `design-system` (`.claude/skills/design-system/SKILL.md`).
- Добавляешь новую метрику — проектный скилл `add-metric`.
- Трогаешь загрузку файлов, пакет агрегатов, логи, хранение — проектный скилл `privacy-guard`.

## Жёсткие правила (никогда не нарушать)

1. **Тексты сообщений пользователей никогда не попадают в логи, Google Sheets, аналитику и ошибки.** Даже обрезанные.
2. Персональные данные (email, Telegram ID, имена, платежи) хранятся только в PostgreSQL на сервере в РФ. В Google Sheets — только псевдонимный `user_ref`.
3. Образцы реальных экспортов лежат в `samples/` — папка в `.gitignore`, **никогда не коммить** её содержимое. Для тестов используй синтетические фикстуры (`docs/20-testing.md`).
4. Код платных метрик живёт **только на сервере** (`apps/api/app/metrics/paid/`). В браузер уходят только бесплатные метрики и сборщик пакета.
5. Начисление и списание разборов — только через журнал `ledger` в одной транзакции (см. `docs/09-billing-runs-promo.md`).
6. Webhook платёжки не доверяем: перезапрашиваем платёж по id через API провайдера.
7. Секреты — только в `.env` (в `.gitignore`) и GitHub Secrets.

## Стек (коротко, подробно — docs/02)

- Монорепо: `pnpm` workspaces (TS) + `uv` (Python).
- Web: React 18 + Vite + TypeScript, CSS Modules + CSS-переменные из дизайн-токенов, Radix Primitives (без готовых UI-китов).
- Парсинг в браузере — в Web Worker.
- API: FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16, Redis + arq (фоновые задачи).
- Бот: aiogram 3 (webhook), локальный `telegram-bot-api` сервер для файлов > 20 МБ.
- Отчёты: Jinja2 + серверные SVG-графики; PDF/PNG — Playwright (Chromium).
- Логи: structlog (JSON).
