# Как работать над проектом с Claude

## Процесс
1. Вы пишете задачу или «Фаза N» (промпты — в ROADMAP).
2. Claude читает CLAUDE.md и документы фазы, пишет код, сам запускает тесты и линтеры (вы только подтверждаете действия).
3. Если вы просите «сначала покажи» — Claude присылает подробный отчёт и ждёт вашего «можно».
4. **Один коммит и пуш в конце** ответа, в рабочую ветку. Деплой — только по вашей команде (кнопка Deploy в GitHub + ваше подтверждение).
5. Изменилось решение — Claude обновляет документ в том же коммите.

Effort: **high** — дизайн, деньги, парсеры, бот, прод; **medium** — остальное.

## Скиллы
- Подключённые к аккаунту скиллы Claude использует сам, когда задача подходит; можно и попросить явно («используй dataviz»).
- Установить скилл в ваш аккаунт Claude не может (может показать карточку-предложение, если в каталоге есть подходящий — для дизайна пока не нашлось). Зато проектные скиллы лежат в репозитории (`.claude/skills/`) и работают в любой сессии с ним: `design-system`, `add-metric`, `privacy-guard`.
- Видно ли, что скилл включился: да — вызов скилла отображается в ленте отдельным шагом; плюс правило в CLAUDE.md: первой строкой `🔧 Скилл: <имя> — <зачем>`.

## Заполнение контекста
- Терминальная версия Claude Code: строка статуса (`/statusline`) может показывать процент под полем ввода.
- Везде: команда `/context` показывает текущее заполнение.
- Постоянный индикатор в приложении — отдельный небольшой мод интерфейса; скажите «сделай индикатор контекста», и Claude сделает его отдельно от проекта.

## Образцы данных
Большие экспорты не читаются через подключение к Google Диску — запустите ячейку из [samples-schema.md](samples-schema.md), она положит рядом маленькие схемы без текстов, и Claude прочитает их.

## Проверка перед пушем
Если в сессии недоступна командная строка (так было при создании v0.1), Claude честно пишет, что тесты не запускались, и предлагает: пуш → проверка в GitHub Actions (CI запускается на каждый пуш) → исправления следующим коммитом; либо новую сессию с командной строкой.
